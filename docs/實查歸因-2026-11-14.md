# 實查歸因（M0／M1）

> 日期：2026-11-14
> 語料：自家 3 個 WPF 應用程式 ＋ 17 個公開專案（分四輪：7 → 13 → 16 Avalonia → 17＋ MAUI），約 5,600 個 XAML 檔
> 結論：**第一版在公開專案上吐出約 36,000 筆假警報。自家語料一筆都測不到。**

---

## 0. 這份文件存在的理由

XamlContrast 的規劃書第 8.3 節寫下過一條憲法修正：

> 「每條規則來自實查」要加一句 —— **實查的樣本必須包含非作者的專案。**

它當時的數據是：四個自家專案的解析覆蓋率 89~100%，八個公開專案合計 **9.6%**。
同一個工具、兩個數量級。

XamlKeys 從一開始就照這條做，結果**一模一樣**。下面是逐項紀錄。

### 3.3 開發期間自己出過的一個錯：假的進步

修到一半時，`ProjectIndex` 收的是**絕對路徑**，但 finding 帶的是**相對路徑**
（baseline 要跨 OS 可攜）。`Path.GetFullPath` 於是對著行程的工作目錄解析，
結果**每一個引用都比對不到專案**，整批被當成「函式庫、跨專案」而靜默跳過。

表面上，wpfui 的 289 筆 `out-of-scope` 歸零了，看起來像修好了。
實際上是整類檢查被關掉。

這跟 XamlContrast 規劃書 8.1 節「工具自己出過四次錯，每一次都是**謊報健康**」是同一種病。
抓到它的方式也一樣：**示範專案的計數斷言**紅了（`out-of-scope` 從 1 變 0），
而那個斷言之所以存在，就是為了抓「擋的數量莫名其妙變動」。

## 4.2 第三輪語料：Avalonia（同日）

ROADMAP 原本把 Avalonia 列在 1.x，條件是「要有真實專案當白老鼠」。拿到了三個：
**AvaloniaUI/Avalonia 本身（577 axaml）、FluentAvalonia（191）、Semi.Avalonia（404）**。

### 合併順序：不靠猜，去讀原始碼

`Avalonia.Base/Controls/ResourceDictionary.cs` 的 `TryGetResource`：

```csharp
for (var i = _mergedDictionaries.Count - 1; i >= 0; --i)
```

**反向搜尋 = 後宣告的贏 = 與 WPF 相同。** 所以不需要第三種方言。
同一段程式碼也確認了：字典自己的項目最優先、ThemeDictionaries 次之、合併字典最後；
而 `ThemeVariant.Default` 是「要求的 variant 沒有對應字典時」的退路 ——
這一條讓我把 `Default` 的分側邏輯整個拿掉，改成一律中性（往少報的方向錯）。

### 第三輪的假警報

| 假警報 | 筆數 | 成因 |
|---|---:|---|
| Avalonia `dangling`（`SystemAccentColor` 等） | 162 | 執行期前綴規則只對 WinUI 生效 |
| ModernWpf `dangling-dynamic`（`SystemColor*`） | 48 | 同上（WPF 專案也會用到系統色鍵） |
| Semi.Avalonia `shadowed` | 66 | 主題用**目錄**分，側別沒有往下傳 |

### 第三輪的五條規則

| # | 規則 | 來源 | 不做會怎樣 |
|---|---|---|---|
| 23 | `<ResourceInclude Source>` 等同 `<ResourceDictionary Source>` | 全部三個 | 整個作用域變成不可知 |
| 24 | `avares://組件名/路徑` 的解析 | Semi.Avalonia | 跨組件的合併解析不到 |
| 25 | `<X.Styles>` 裡的 StyleInclude 與函式庫主題物件會帶資源進來 | Semi.Avalonia、FluentAvalonia | 那些資源等於不存在 |
| 26 | 執行期前綴（`SystemAccentColor…`／`SystemColor…`）在**每一種方言**都算 | Avalonia、ModernWpf | 210 筆假 dangling |
| 27 | 主題入口包含的字典要繼承它的側別；**同一群組的不同入口 = 互斥** | Semi.Avalonia | 66 筆假 shadowed |

規則 27 又踩到一次「只看表面」的陷阱：第一版用「同一個群組 id」去判，
而 Semi.Avalonia 把同一套 ThemeDictionaries 在 `SemiTheme.axaml` 與 `Index.axaml`
各宣告了一次 —— `Themes/Dark/_index.axaml` 因此是從**兩個**群組被合併到的，整批漏掉。
正確的說法是「存在某個群組，兩者分別來自它的**不同入口**」。

### 第三輪之後

| 專案 | fail | warn | info |
|---|---:|---:|---:|
| Avalonia | 0 | 36 | 14 |
| FluentAvalonia | 0 | 3 | 588 |
| Semi.Avalonia | 0 | 0 | 646 |

而且十二個非 Avalonia 專案逐筆比對，**沒有任何一筆 finding 因此消失或改變**，
只有三個專案的 `external`／`dangling-dynamic` 往下降（那正是規則 26 修掉的）。

## 4.3 第四輪語料：.NET MAUI（同日）

README 寫了「WPF、WinUI、Avalonia」之後，順手探第四個生態系會不會整個壞掉。**會。**

白老鼠：**dotnet/maui-samples（1,238 個 xaml、231 個獨立範例專案）、dotnet/eShop**。

第一次跑的結果：

| | xaml | 鍵 | fail |
|---|---:|---:|---:|
| maui-samples | 1,238 | **0** | **19,156** |
| eShop | 25 | **0** | **239** |

**零個鍵。** 原因只有一條：MAUI 的 `x:` 命名空間是
`http://schemas.microsoft.com/winfx/2009/xaml`，而 WPF／WinUI／Avalonia 是 **2006**。
我把 2006 寫死了，於是每一個 `x:Key` 都看不見（1,238 個檔裡有 1,122 個是 2009）。

| # | 規則 | 來源 | 不做會怎樣 |
|---|---|---|---|
| 28 | `x:` 指令要認 **2006 與 2009 兩個命名空間** | maui-samples | MAUI 專案 0 個鍵、19,395 筆假懸空 |
| 29 | 「程式載入的字典」比對要限定在**同一個專案**裡 | maui-samples（231 個範例） | 任一個範例提到 `Colors.xaml`，其餘 230 份全被豁免 |

修完之後：maui-samples 4,361 個鍵、40 筆 fail；eShop 130 個鍵、0 筆 fail。
而那 40 筆**全是真的** —— `ThemePrimary`、`TextPrimaryColor` 之類的鍵
在整個 maui-samples repo 都沒有定義。

十五個既有專案逐筆比對，**沒有任何 finding 因此改變**。

### 一個順帶的觀察

231 個 MAUI 範例裡有 **122 個的 `App.xaml` 根本沒有 `MergedDictionaries`**，
而它們的 `Resources/Styles/Styles.xaml` 照樣引用 `Colors.xaml` 裡的鍵。
工具把這件事報成 472 筆 `out-of-scope`（warn）—— 以靜態證據而言這是準確的：
那些範例確實沒有把字典接起來。

## 4.4 第一次真的拿來用：Kindling（同日）

前四輪都是「掃別人的專案、看報告對不對」。這一輪是照 README 的導入流程，
真的在自家 App 上用一次 —— 第一筆 finding 就是錯的。

`Blue` 被報成沒人用。實際上它在 `MessageDialog.xaml.cs`：

```csharp
(string Glyph, string BrushKey)? icon = image switch { ... => ("glyph", "Blue"), ... };
IconText.SetResourceReference(TextBlock.ForegroundProperty, ic.BrushKey);
```

鍵名先放進變數、再交給查找。工具兩邊都沒看到：`SetResourceReference` 的**變數**版本
連「動態查找點」都沒算（只認 `FindResource` 與 `Resources[...]`），於是 summary 連一句
「這裡有你看不到的東西」都沒有。照工具說的刪掉，資訊對話框的圖示就失去顏色 ——
**正好是這支工具最不該犯的錯**。

回頭拿語料量，洞比 Kindling 大：

| 寫法 | 語料裡的數量 | 原本 |
|---|---:|---|
| `SetResourceReference(prop, 變數)` | 52 | 不算查找點 |
| Avalonia `TryGetResource("K", …)` | 44 | 看不到 |

### 不是字串的鍵：`{x:Static …Key}` 與 `ComponentResourceKey`（同日）
